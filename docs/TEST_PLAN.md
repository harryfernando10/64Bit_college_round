# Test Plan and Controlled Evaluation

`.venv/Scripts/python.exe -m pytest` runs API, schema, curated fixture and deterministic baseline cases offline. `data/evaluation/cases.json` contains 12 stable, single-claim cases with expected labels and rationales, including one paraphrase claim supported by a deterministic mocked NLI output; run them through the actual API with `.venv/Scripts/python.exe -m pytest tests/test_evaluation.py -q -s -p no:cacheprovider`. This prints verdict counts, an expected-to-observed confusion count, and exact-label accuracy. `data/evaluation/stress_cases.json` adds three stable API workflow cases covering source removal, passage removal and passage editing, including baseline/source immutability checks. The dataset is deterministic and intentionally aligned with implemented narrow rules; exact-label accuracy is only a fixture regression count, not an estimate of general reliability or real-model performance.

The broader controlled examples in `tests/test_api.py` cover supported exact text, quantity/date mismatch and unrelated-value abstentions, scoped and quoted polarity, paraphrased support, irrelevant evidence, missing detail, conflicting sources, Unicode offsets, multi-document retrieval, quote integrity, duplicate IDs and modified fixtures. Mocked verifier cases cover paraphrased entailment, contradiction, neutral output, irrelevant passages excluded by retrieval, negation, numeric/date disagreement, conflicting documents, errors and missing local model files. They are constructed test cases, not a representative benchmark of real-world hallucinations.

No model weights were downloaded and no actual NLI inference smoke test was run in the implementation environment. The model adapter has only offline mocked integration coverage here.

Evaluation status: controlled suite measures contract behavior and includes all four verdict paths (fourth via conflicting sources and the curated fixture set). Phase 3 stress tests include reproducible source removal with support loss (SUPPORTED → INSUFFICIENT_EVIDENCE), removal of irrelevant evidence (SUPPORTED remains SUPPORTED), and editing an exact supporting passage to a paraphrase (SUPPORTED → INSUFFICIENT_EVIDENCE in baseline mode). These are observations of narrow test inputs, not expected universal outcomes. The suite is too small and intentionally rule-aligned to report meaningful per-verdict precision, recall, F1, confusion matrix or macro-F1; those metrics are therefore excluded rather than presented as general performance. Evidence sensitivity is not a test of parametric memory leakage. Count is the number of passing automated tests at execution time, reported in the delivery summary. No cases are claimed as a benchmark.

Stress endpoint tests additionally validate passage eligibility, invalid IDs/edits, fixture comparability warnings, source/baseline immutability, and exact excerpt/offset integrity for perturbed context. Optional NLI continues to be covered with deterministic mocks; no model downloads or keys are required.

The frontend production build runs `npm run build` and performs TypeScript checks. Manual browser checks: load each scenario; edit an answer and confirm old results clear; run a custom audit; verify exact spans and source quotes; add a source; restore the selected scenario; inspect baseline/fixture disclosures; submit invalid empty material; stop backend and confirm API error state.

Known edge cases include abbreviations, decimal/punctuation segmentation, paraphrase verification, tables or structured source text, and ambiguous numeric context. Quote validity does not imply entailment. No frontend browser automation is configured.
