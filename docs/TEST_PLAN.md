# Test Plan and Controlled Evaluation

`.venv/Scripts/python.exe -m pytest` runs API, schema, curated fixture and deterministic baseline cases offline. `data/evaluation/cases.json` contains 12 stable, single-claim cases with expected labels and rationales, including one paraphrase claim supported by a deterministic mocked NLI output; run them through the actual API with `.venv/Scripts/python.exe -m pytest tests/test_evaluation.py -q -s -p no:cacheprovider`. This prints verdict counts, an expected-to-observed confusion count, and exact-label accuracy. `data/evaluation/stress_cases.json` adds three stable API workflow cases covering source removal, passage removal and passage editing, including baseline/source immutability checks. The dataset is deterministic and intentionally aligned with implemented narrow rules; exact-label accuracy is only a fixture regression count, not an estimate of general reliability or real-model performance.

The broader controlled examples in `tests/test_api.py` cover supported exact text, quantity/date mismatch and unrelated-value abstentions, scoped and quoted polarity, paraphrased support, irrelevant evidence, missing detail, conflicting sources, Unicode offsets, multi-document retrieval, quote integrity, duplicate IDs and modified fixtures. Mocked verifier cases cover paraphrased entailment, contradiction, neutral output, irrelevant passages excluded by retrieval, negation, numeric/date disagreement, conflicting documents, errors and missing local model files. They are constructed test cases, not a representative benchmark of real-world hallucinations.

`tests/test_nli_smoke.py` is opt-in: it runs actual local inference only when `REFUTELLA_NLI_MODEL_PATH` points to an existing cached model. Phase 5A downloaded the pinned model to the ignored `models/refutella-nli` directory and ran the test successfully for entailment, contradiction, neutral, and a simple paraphrase. The test is skipped in the normal no-model suite. Separate fallback tests verify that unset or missing local model paths preserve baseline behavior.

Evaluation status: controlled suite measures contract behavior and includes all four verdict paths (fourth via conflicting sources and the curated fixture set). Phase 3 stress tests include reproducible source removal with support loss (SUPPORTED → INSUFFICIENT_EVIDENCE), removal of irrelevant evidence (SUPPORTED remains SUPPORTED), and editing an exact supporting passage to a paraphrase (SUPPORTED → INSUFFICIENT_EVIDENCE in baseline mode). These are observations of narrow test inputs, not expected universal outcomes. The suite is too small and intentionally rule-aligned to report meaningful per-verdict precision, recall, F1, confusion matrix or macro-F1; those metrics are therefore excluded rather than presented as general performance. Evidence sensitivity is not a test of parametric memory leakage. Count is the number of passing automated tests at execution time, reported in the delivery summary. No cases are claimed as a benchmark.

Stress endpoint tests additionally validate passage eligibility, invalid IDs/edits, fixture comparability warnings, source/baseline immutability, and exact excerpt/offset integrity for perturbed context. Optional NLI continues to be covered with deterministic mocks; no model downloads or keys are required.

The frontend production build runs `npm run build` and performs TypeScript checks. Browser end-to-end checks use `@playwright/test`: install Chromium with `npx playwright install chromium`, start FastAPI at `127.0.0.1:8000`, then run `npm run test:e2e` from `frontend/`. The Playwright config starts Vite or reuses the server at port 5173. The suite checks all scenarios, restore behavior, accessible claim selection and traces, the 1–8 shared source UI boundary, custom audit and verdict behavior, all three stress operations, upload UI and TXT/PDF/DOCX extraction through the live backend, editable extracted text, manual/uploaded source composition and removal, unsupported-file recovery, API validation/health, transport failure recovery, responsive overflow, and browser diagnostics. Failure screenshots and traces are retained under `frontend/test-results/` (ignored by Git). Reviewed presentation screenshots are stored in `docs/qa-screenshots/`.

Remaining manual browser checks include true keyboard-only and screen-reader evaluation, stopping/restarting the actual backend, and rapid overlapping submissions. API tests validate malformed extraction requests and format boundaries; source, passage, stale and unknown stress selections are covered by existing service/API tests. Do not label these manual or API-only cases as browser-tested.

Known edge cases include abbreviations, decimal/punctuation segmentation, paraphrase verification, tables or structured source text, and ambiguous numeric context. Quote validity does not imply entailment. The browser suite is regression coverage for current workflows, not a general reliability benchmark; the real NLI smoke test is not an accuracy evaluation.

Phase 5A adds backend regression coverage for obvious non-factual triage, exact span preservation, distinct `not_assessed` totals, explicit inclusion override, source-label order after reordering, and unconfigured/missing-model fallback. The browser suite additionally exercises triage display and user override. Existing fixture, source-driven audit, stress and upload tests remain in the full suite. Actual local NLI inference did not run; no real model result is tested or claimed.

Phase 5A verification on 2026-10-10: full backend suite **53 passed** (the added opt-in NLI test skips without a configured model); focused real-inference smoke **1 passed**; controlled evaluation **12/12** plus **3 stress cases**; Playwright **14/14**; TypeScript/production build passed; `git diff --check` passed.
