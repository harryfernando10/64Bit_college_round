# API Contract — Phase 3

Base path `/api`; UTF-8 JSON. Pydantic models in `backend/models.py` and TypeScript definitions in `frontend/src/types.ts` are canonical. Extra request properties are rejected.

## Endpoints

- `GET /api/health`: status, service name and current phase (3).
- `POST /api/extract-document`: accepts one multipart `file` upload and returns `{filename, file_type, size_bytes, text}` after in-memory text extraction. Supported extensions are `.txt` (UTF-8), `.pdf` (text-based PDFs), and `.docx` (paragraphs and table cells). The filename is reduced to its basename and retained as the source title. The API does not persist files or execute document content.
- `GET /api/scenarios`: curated scenario inputs; these only provide a fixture verdict when scenario ID, answer and entire source list exactly match.
- `POST /api/audit`: source-driven audit for every other valid request.
- `POST /api/stress-experiment`: reruns the same audit engine against a request-local modified copy of a supplied baseline's source context.

Stress request: `{baseline, operation, source_id, sentence_id?, replacement_text?}`. `baseline` is the complete validated `AuditResponse` previously returned by `/api/audit`. Operations are `REMOVE_SOURCE`, `REMOVE_PASSAGE`, and `EDIT_PASSAGE`. Passage operations require a sentence ID that was actually retrieved as evidence in the baseline. Edit requires non-whitespace replacement text that differs from the selected passage. Extra fields and malformed requests return 422; unknown sources/passages, non-retrieved passages, unchanged edits, and invalid modified source documents also return useful 422 errors. If the operation removes all source context, the API responds successfully with `comparable: false`, no perturbed audit, and `NOT_COMPARABLE` claim outcomes.

The experiment response includes its human-readable label and the exact removed/replaced passage, the original baseline, a fresh perturbed audit, per-claim baseline/perturbed findings and outcomes (`CHANGED`, `UNCHANGED`, `UNRESOLVED`, or `NOT_COMPARABLE`), comparability, and warnings. The backend copies source models before editing them. It does not edit fixture files or the baseline. The perturbed run omits the scenario ID so an edited input cannot accidentally select curated fixture output; it uses the regular `run_audit` path and current optional NLI configuration. A fixture baseline or a baseline/perturbed execution-mode mismatch is marked not directly comparable. Verdicts remain observations, not proof of truth, memory leakage, or evidence independence.

Request shape remains `{answer, sources, scenario_id?}`. Answer is 1–20,000 code points, source count 1–8, source text 1–30,000, title 1–160, and IDs match `[A-Za-z0-9_-]+` and are unique. Whitespace-only text is rejected. Invalid input returns HTTP 422.

Document extraction has an independent default upload-byte limit of 10 MiB per file, configurable with `REFUTELLA_MAX_UPLOAD_BYTES`. The endpoint reads at most one byte beyond that limit and returns 413 when exceeded. PDFs are limited to 200 pages and extraction is capped at 30,000 characters. Unsupported extensions return 415. Empty, malformed, encrypted, mismatched-signature, unsupported-encoding, or text-empty documents return a readable 422. A PDF with no extractable text reports that OCR is unsupported. DOCX archives with more than 20 MiB of uncompressed members are rejected as a bounded extraction safeguard. These checks are for the local prototype and are not a full document security scanner. Extracted output should be passed to the existing audit endpoint as an ordinary source; uploaded and manually entered sources share the eight-source maximum.

## Response and semantics

Response retains `audit_id`, `execution_mode`, exact input echo, `source_sentences`, `claims`, `summary` and `warnings`. Mode is `FIXTURE` for an exact curated fixture; `BASELINE` when the optional verifier is not configured; `MODEL` when local NLI weights and dependencies loaded for the audit; `MODEL_UNAVAILABLE` when local verification was explicitly configured but cannot be loaded. NLI is only called for retrieved, eligible, unquoted passages, so a model-mode audit may contain claims without model calls. No audit-time model download or network access occurs. Claims add `semantic_verifications`, with one record per checked passage: status (`ENTAILMENT`, `CONTRADICTION`, `NEUTRAL`, `INCONCLUSIVE`, `UNAVAILABLE`, or `ERROR`), source/sentence IDs, model ID, raw logits and detail. All custom claims retain original text and half-open Python Unicode code-point offsets.

- `SUPPORTED`: in baseline mode, normalized textual identity with a supplied passage; in model mode, at least one retrieved passage receives a decisive NLI entailment result and no deterministic/model conflict applies. Neither means the source is authoritative or the statement true in the world.
- `CONTRADICTED`: in baseline mode, one comparable numeric value with matching units or one comparable date differs, with highly overlapping content context and no competing values/dates; or narrowly scoped negation/antonym wording differs while the remaining unquoted token sequence is identical. In model mode, at least one retrieved passage receives a decisive NLI contradiction result and no conflict applies. Deterministic rules are deliberately narrow and model results are fallible.
- `AMBIGUOUS`: baseline finds directly contradictory supplied passages or a limited causal qualification pattern; or the model and deterministic checks conflict, multiple decisive NLI outputs disagree, or model outcomes are only partially available in conflict with decisive ones.
- `INSUFFICIENT_EVIDENCE`: everything else, including retrieved but inconclusive passages and no retrieval.

Retrieval uses deterministic BM25-style term-frequency ranking within supplied sentences. The highest eligible passage from each supplied source is reserved before adding further candidates, so a verbose source does not crowd every other document out; up to `max(3, source_count)` passages are returned (eight sources is the API maximum). The score is internal discovery ranking only and is not exposed as confidence. Quoted passages are not used by deterministic checks or the exact-text support rule because attribution is unresolved. Exact quotation and source span integrity are checked by Pydantic; a validated quote proves presence, not relevance or truth. The current lightweight sentence splitter can mishandle abbreviations and some punctuation patterns.

NLI is opt-in through `REFUTELLA_NLI_MODEL_PATH`, which must point to a local directory. The model is loaded lazily on the first non-fixture audit, with `local_files_only=True`. If loading fails, `MODEL_UNAVAILABLE` is returned and semantic verification is not replaced by another model. Deterministic rules still run independently. The NLI adapter compares each selected source passage as premise with the unmodified claim as hypothesis, never supplies evidence, and refuses to truncate pairs beyond 512 tokens. Scores in `raw_logits` are classifier logits, not probabilities. Top-class softmax and margin cutoffs are uncalibrated abstention heuristics. Neutral/inconclusive output does not support a claim; conflicting NLI and deterministic results yield `AMBIGUOUS`.

Summary counts must exactly match returned claims. Fixture outputs remain curated and are disclosed as fixtures. Validation, retrieval or API failures are not converted into confident findings. Empty answers and duplicate IDs return 422.

## Phase 5A credibility and claim triage

Every source-driven answer span remains visible with exact Unicode code-point offsets and an ordered `claim-N` ID. Narrow rules mark obvious questions, common imperative starts, short unpunctuated headings/labels, and explicit first-person opinion wording `NOT_ASSESSED`. These records remain in the response and in `total_claims`; they are counted separately in `summary.not_assessed`, never merged with insufficient evidence. The caller can include flagged claim IDs in `assess_claim_ids` to run the normal audit rules; the finding retains its triage explanation. This is a transparent heuristic, not an NLP classifier. Fixture mode continues to return its curated findings.

Every audit response includes `source_labels` mapping stable source IDs to ordered `S1`, `S2`, etc. Labels reflect the current request order after removal/reordering; IDs remain the traceable identity. The UI emphasizes label and title, with the stable ID available in detail/hover and all API evidence references.

Findings provide a plain-language summary and a separate technical-details disclosure for rule/verifier mode, source and passage references, excerpts, offsets, checks, model outputs, and warnings. “Exact quote found” means only that the excerpt exists at the returned source offsets. Retrieval means a passage was selected as relevant; it does not establish support. NLI outputs are raw uncalibrated classifier scores, not truth probabilities. `NOT_ASSESSED` is distinct from all four evidence verdicts.
